## How I’ll use this repo

1. Open the official case study page and use its interactive SQL environment and data.
2. Attempt each question before looking at outside solutions.
3. Save my own query in that week’s `solutions.sql` file. Add comments where assumptions or business logic need explanation.
4. Record results, difficult questions, and concepts practiced in `notes.md`.
5. Commit each week when the work is ready to share.

## Suggested 8-week rhythm

- **Days 1–2:** Read the case study, inspect the schema and data, and attempt the questions.
- **Days 3–4:** Refactor queries for clarity; check edge cases and validate intermediate results.
- **Day 5:** Write a short summary of the business findings and what you learned.
- **Days 6–7:** Catch up, review, and share a progress update if you choose.

The original challenge has no fixed start or end date. Set your own pace and adapt this schedule as needed.
